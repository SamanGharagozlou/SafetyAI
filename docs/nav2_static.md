# Static navigation on a lidar map (branch `nav2`)

Goal: use the dashboard with the **lidar maps in `maps/`** (made with the MetaCam Lite, see `docs/map_localization.md`), get a **costmap**
and navigate with **Nav2**. "Static" = the map is a saved file; there is no live mapping and no live obstacle sensing yet.
The monocular SLAM path is deactivated (`docs/mono_slam.md`).

## What runs
```
map_server (lidar map.yaml) ──▶ /map
initial_pose_localizer  ──▶ TF map→odom   (from the pose you place; bridge gives odom→base_link/base_footprint)
Nav2: planner (NavFn A*), controller (MPPI, omni), BT navigator, behaviours, velocity smoother ──▶ /cmd_vel ──▶ agibot_d1_bridge
costmaps: global = static layer + inflation (unknown space is not traversable); local = rolling 4x4 m, static layer + inflation
```
Launch file: `ros2 launch d1_nav static_navigation.launch.py map:=<repo>/maps/<scan>/map.yaml [x:= y:= yaw:=]`
Params: `d1_nav/params/nav2_params_static.yaml`, generated by `d1_nav/tools/make_nav2_params.py` (edit the script, not the file).
Footprint 0.63 x 0.36 m, inflation radius 0.45 m, speed limits vx 0.30 / vy 0.20 / wz 0.50.

## Dashboard workflow
```bash
ros2 launch d1_dashboard dashboard.launch.py robot_ip:=<ip> local_ip:=<pc-ip>            # add external_robot:=true if a bridge already runs
```
Open http://127.0.0.1:8080
1. **Start process**: the robot link (bridge). Stand the robot (control corner).
2. Pick a map in the list and **Load map**: starts map_server, the localizer and Nav2. The list shows the repo's `maps/*` and your saved maps (★).
3. **Place robot**: press on the map where the robot really stands and drag toward the way it faces. Or press *robot is at the map origin* if it stands at the scan start.
   Navigation is **refused until the robot is placed** (odometry alone does not know where it is in the map).
4. **Nav mode**, click a goal (drag sets the heading). The plan, the global/local costmaps (Layers panel) and the trail show progress. E-STOP always works.
5. **Save map + start pose**: copies the loaded map to `~/d1_maps/maps/<name>/` with `meta.json` (start pose). Loading a saved map places the robot automatically.
6. **Clear all** stops everything (the robot link stays if the robot is standing).

API additions: `GET /api/maps` (lidar maps first), `POST /api/workflow {action: load_map | save_map}`, `POST /api/pose {x,y,yaw}` (same as RViz "2D Pose Estimate").
The `d1_gateway` WebSocket gateway sends goals to the same `navigate_to_pose` action, so frontends work on the loaded map too.

## RViz2 view
`ros2 launch d1_nav static_navigation.launch.py map:=... rviz:=true` (works with both localizers) opens RViz2 with `d1_nav/rviz/static_nav.rviz`:
lidar map (white/black/grey), global costmap (blue->red, cyan inscribed, magenta lethal), local costmap (off by default), plan, robot footprint, TF.
Tools: **2D Pose Estimate** = Place robot (`/initialpose`, the localizer picks it up), **2D Goal Pose** = navigate (`/goal_pose`; unlike the dashboard it does not check that the robot is placed).
Checked 2026-11-15: RViz loads the config without errors, the map and costmaps display, and a goal sent on `/goal_pose` was reached in simulation (no screenshot was taken; please look at it once).

## How the map looks (RViz style)
White = free floor, black = wall/obstacle, grey = not scanned. Costmap overlay (Layers: Global / Local costmap): blue -> red gradient = rising cost,
cyan = robot centre may not enter, magenta = lethal. "Hide stray dots" cleans the *display* only (isolated black cells and thin ray-cast spikes); the map file is untouched.

## Unknown space bug (fixed in `static_navigation.launch.py`)
The lidar maps mark "not scanned" as pixel 205 with `free_thresh: 0.25`. map_server turns 205 into p = 0.196 < 0.25, i.e. **free**, so 43% of the first map
(115,827 cells) loaded as free and Nav2 would plan through areas the lidar never saw. The launch now writes a patched copy (`/tmp/d1_nav_maps/<map>.yaml`,
`free_thresh` 0.19) so those cells stay unknown (the global costmap does not plan through unknown). Verified: `/map` = 115,827 unknown / 153,699 free / 1,591 occupied.
`d1_localization/localize.launch.py` on its own still loads such maps with the unknown area as free; set `free_thresh: 0.19` in the map's yaml there.

## Limits (be aware)
* **No live localization.** The robot moves in the map by odometry (body velocity + IMU yaw) and drifts; re-place it when it has. Heading drifts ~9 deg/min when standing still.
* **No live obstacles.** The costmap is the saved map: people, moved boxes and anything the scan missed are invisible. Low obstacles are weak in the first map (see `maps/README.md`).
* Unknown (grey) map areas are not traversable; the start must lie in free space. Pick the map scan whose origin you can reproduce.
* The first start can race with a Nav2 that is still shutting down; wait ~10 s after *Clear all* before loading again.
* Not yet tested on the real robot (the 2026-11-15 session was blocked by its battery).
