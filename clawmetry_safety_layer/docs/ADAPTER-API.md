# Adapter API: edge and brain endpoints (for the ClawMetry adapter)

Two HTTP services make up the D1 Ultra-W venue stack. Topology and keys are in `docs/REMOTE-OPS.md`.

| Service | Where | Base URL (tailnet) | Key header | Start |
|---|---|---|---|---|
| **Edge**: skill server, safety FSM, perception, concierge client | venue PC next to the robot | `http://edge:8765` | `X-Api-Key: $EDGE_API_KEY` | `make edge` (`python -m skills.edge`) |
| **Brain**: Cosmos relay, mission-control console, concierge | this DGX Spark | `http://spark-7a33:8780` | `X-Api-Key: $BRAIN_API_KEY` | `make brain` (`python -m brain`) |

Live OpenAPI (generated by FastAPI, always current): **`/docs`** (Swagger UI) and **`/openapi.json`** on both services,
e.g. `http://edge:8765/docs` and `http://spark-7a33:8780/docs`. The edge serves them only with the key header when
called from another machine.

## The rule for the adapter: goals only, never velocities

The adapter sends **goals**: `guide_to`, `say`, `ask`, `pause` / `resume`, `approve` / `deny` / `reset`, and policy
edits. It **never sends velocities**. Neither service has a velocity endpoint, and none will be added. Every goal goes
through the same local zone policy, speed caps, L1 geofence and safety FSM as the MCP tools, in the edge process next to
the robot. A goal can be refused (`blocked_by_policy`, `held by safety`); it can never make the robot faster or less
constrained. When the link drops, the edge slows down (CAUTION) or holds at the next waypoint. It never keeps going on
a stale remote command.

## Auth

* Every request from another machine carries `X-Api-Key`. A wrong or missing key gets `401 {"detail": "X-Api-Key
  required"}`.
* Loopback callers on the edge (the MCP server in proxy mode, the local agent, ClawMetry's local daemon) don't need the
  key.
* If a service has no key configured, it refuses all remote calls (fail closed).
* Keys live in `.env` (git-ignored). The same `EDGE_API_KEY` and `BRAIN_API_KEY` values go on both machines.
* The brain console in a browser logs in once with `BRAIN_API_KEY` and gets an HttpOnly, SameSite=Strict cookie.

## Edge endpoints

### `GET /health`
`{"ok": true, "body": "agibot_d1w", "monitor": true, "controller": "<ClawMetry controller id>"}`

Field notes:

* **`safety.state`** is one of `NORMAL | CAUTION | HOLD | RECOVER`.
* **`speed_cap`**: `null` means the policy caps apply; `0.15` in CAUTION; `0.0` in HOLD and RECOVER.
* **`causes[]`** entries are `{key, source: L1|L2|L3|link|operator, level: caution|hold, reason, policy}`.
* **`latched`** holds the policy hold that needs Reset and then Approve.
* **`robot.mode`** is one of `standing | walking | idle | damped | no_state`. `no_state` means the edge handed over:
  no robot state for 1 s.

```json
 "detections": [{"class": "person", "conf": 0.81, "box": [x1, y1, x2, y2]}], "detector": "team", "detector_age_s": 0.2,

 "nearest_person_m": 1.6, "people_within_2m": 1, "child_near": false,
 "boundary": {"detector": "floor_transition", "ahead_m": 2.57, "floor_here": "concourse_tile", "floor_ahead": "wood",
              "no_go_ahead": false, "fix": null, "confidence": 0.49},
 "scene": "unknown", "scene_conf": 0.0, "camera_off": false, "degraded": []}
```
`degraded` can contain `detector_stale`, `l2_people_disabled`, `boundary_uncalibrated`, `scene_unavailable`,
`no_frame` and `camera_off_zone`.

### `GET /events`: server-sent events, one JSON object per `data:` line
It first replays the last 20 events, then streams live. A `: keepalive` comment arrives every second when idle. Every
event has `ts` and `kind`; the other fields depend on the kind:

| `kind` | Payload (besides `ts`, `kind`) |
|---|---|
| `fsm.transition` | `from`, `to`, `reason`, `source` (L1 / L2 / L3 / link / operator) |
| `breach_predicted` | `source: "L1"`, `basis` (`measured_motion` or absent = our own command), `t`, `at`, `zone`, `breaches[]`, `command` |
| `person_near` | `source: "L2"`, `level` (`slow` 1–2 m / `stop` < 1 m), `distance_m`, `child`, `people_within_2m` |
| `hazard` | `source` L2 (`detector`, `ahead_m`, `floor_here`, `floor_ahead`) or L3 (`hazards[]`) |
| `judge_verdict` | `leaves_go_zone`, `hazards`, `people_within_2m`, `stop`, `confidence`, `reason`, `latency_s`, `trigger`; or `judge_unavailable`, `error` |
| `recover` | `phase` (`plan` / `done` / `aborted`), `distance_m`, `moved_m`, `ok`, `detail`, `start`, `end` |
| `approval` | `tool` (`resume_after_hold` / `guide_to`), `decision` (`allow` / `deny` / `pending_console` / `no_rule` / `unavailable`), `poi`, `approval_id`, `by` |
| `guide` | `phase` (`request` / `refused` / `stopped` / `arrived`), `poi`, `nearest`, `reason`, `zone`, `duration_s` |
| `concierge.turn` | `text`, `lang`, `reply`, `actions[]`, `source` (`brain` / `local`), `degraded` |
| `alert_staff` | `reason`, `zone`, `poi` |
| `link_lost` / `link_restored` | `link` (`brain` / `control_plane`), `brain_error` / `control_plane_age_s` |
| `handover` / `state_restored` | `reason` (`no state for 1 s` / `robot reports disconnected`), `transport`, `was_moving` |
| `tilt_breach` / `tilt_cleared` | `tilt_deg`, `cap_deg` |
| `pose.refix` / `pose.calibrated` / `landmark_seen` | `landmark`, `drift_m`, `odom_to_zone` / `tag_id`, `range_m`, `bearing_rad` |
| `breach` (monitor) | `rule`, `severity`, `zone`, `value`, `cap`, `detail`, `action`, `active` |
| `command.refused`, `damp.refused` | `command`, `reason` |
| `turn.begin` / `turn.end` | `skill`, `args` / `outcome`, `message` |

The same events also go into the ClawMetry robot-session journal (`docs/ROBOT-SESSIONS.md`), with the full turn trace.

### `POST /ask`: the concierge
Request `{"text": "Wie viel kostet ein Tagesticket?", "lang": "de" (optional), "session": "kiosk-1" (optional),
"name": "Anna" (optional)}`.

* **From the QR onboarding:** send `name` and `lang` with the guest's first message and keep the same `session`. The
  concierge greets the guest by name once, and keeps the language for the session until a message brings another.
* **The name stays out of the journal:** the `concierge.turn` event records `named: true` and writes `<guest>` in place
  of the name. The name goes to the brain (and from there to the Anthropic API) only.
* **Promotions:** a reply that started a guided walk may carry one promotion (`promotion: "<id>"`; on the brain path an
  `actions` entry `{"type": "promotion"}`). At most one per walk, never while a hold is active (`venue/promotions.yaml`).
Response:
```json
{"reply": "Ein Tagesticket kostet für Erwachsene CHF 39.", "actions": [{"type": "guide_to", "poi": "bath_entrance", "ok": true,
 "message": "guiding to bath_entrance"}], "lang": "de", "source": "brain", "model": "claude-opus-5-5", "latency_s": 2.4,
 "degraded": null}
```
* `source: "local"` means the brain or the Anthropic API was unreachable and the edge answered from the venue facts. In
  that case `degraded` says why.
* The reply is also spoken: the `/say` topic, plus local TTS if installed.

### `POST /greet`
Request `{"name": "Anna" (optional), "lang": "de"}`. The robot says hello, by name if given. Response: a SkillResult
with `gesture` (`"shake_hand"` or `null`) and `voice_only_because` (a list of reasons).

The gesture runs only when **all** of these hold:
* `allow_greeting_gesture: true` in the config (default **false**);
* the robot is stationary;
* safety is NORMAL;
* nobody is within 1.5 m, and people detection is working;
* the battery is above 30 %.

Otherwise the greeting is voice only. It never moves the base. The MCP tool `greet` is the same. The gesture is the
team bridge's `~/shake_hand`, or, with `greeting_robot_cmd` set in the config, that one string on `/robot_cmd`
(`gesture: "robot_cmd:<string>"`); posture and locomotion commands are refused.

### `POST /say`
Request `{"text": "..."}`. The robot says it on `/say` (`std_msgs/String`, for the team's voice stack) and through local
TTS. The response is a SkillResult (below).

### `POST /guide_to`
Request `{"poi": "bath_entrance", "lang": "en", "wait": true, "rationale": "guest asked"}`.

* `wait: false` starts the guide and returns at once: `{"ok": true, "started": true, "poi": "bath_entrance"}`.
* `wait: true` returns the full SkillResult when the guide ends.
* No-go POIs are refused immediately:
  ```json
  {"ok": false, "skill": "guide_to", "message": "blocked_by_policy: I can't go to the pools: ...", "blocked_by_policy": true,
   "poi": "pool_deck", "nearest": "bath_entrance", "nearest_name": "Therme entrance", "staff_escort": "requested",
   "confirmed_state": {"...": "robot dict"}, "duration_ms": 3.1}
  ```

POIs: `GET /pois?lang=de` returns `[{"id", "name", "zone", "no_go", "nearest"}]`.

### SkillResult (every `/skills/*`, `/say`, `/guide_to`, `/pause`, `/resume` response)
`{"ok": bool, "skill": str, "message": str, "confirmed_state": {robot dict}, "duration_ms": float, ...extra}`. Extra
keys appear by case: `blocked_by_policy`, `breach_predicted`, `safety` (FSM snapshot), `monitor_stop`,
`consecutive_failures`, `deviation`.

### `POST /pause`, `POST /resume`
* `/pause` takes `{"reason": "operator"}` (optional). It latches the pause and calls `stop_and_settle()`: zero
  `cmd_vel`, the robot keeps its stance. It never damps.
* `/resume` clears the pause latch. It does **not** clear a safety HOLD; that takes `/reset` and then `/approve`.

### `POST /reset`, `POST /approve`, `POST /deny`
Request `{"by": "<operator name>"}`.

* **`/reset`** is the same as ClawMetry Reset: it backs the robot into the go zone if needed (at most 1.5 m at
  0.15 m/s), then re-arms it. A policy hold then waits in RECOVER with `awaiting_approval: true`.
* **`/approve` and `/deny`** first decide a pending staff escort (`escort_pending`), otherwise a resume after a policy
  hold. Response `{"ok", "decided": "staff_escort" | "resume_after_hold", "safety": {...}}`.
* The same decisions arrive from ClawMetry's Approve/Deny queue once the Guard rules exist (`docs/D1W-RUNBOOK.md`,
  Sunday checklist).

### `POST /confirm`, `POST /refix`, `POST /look`, `POST /alert`, `POST /verdict`
* **`/confirm`**: a person confirmed a load or hand-off (pick/place on the quadruped).
* **`/refix`**: `{"landmark": "pillar"}` re-zeroes odometry drift and returns `{"landmark", "drift_m", "odom_to_zone"}`.
* **`/look`**: `{"question": "what does the sign say?"}` returns `{"scene", "people_within_2m", "detections", "camera_off", "description"}`.
  Cosmos describes one fresh frame through the brain; the frame is dropped afterwards.
* **`/alert`**: `{"reason": "..."}` emits an `alert_staff` event.
* **`/verdict`**: brain to edge only. The body is a verdict (below).

### `GET /policy`, `PUT /policy`
* **`GET /policy`** returns the behaviour policy: `{"path", "policy": {...}, "zones": [...], "quiet_now": bool}`.
* **`PUT /policy`** replaces the whole document. It is validated (422 with `{"errors": [...]}` if invalid), saved, and
  logged as `policy.changed` with who and when. Send the `X-Operator` header to name the person.
* Policy edits are goals too: they cannot raise the bridge's hard caps (0.4 / 0.15 / 0.6), which live in code.

### Skills (same as the MCP tools)
`POST /skills/{get_state | navigate_to | pick | place | say | look_at | hold_pose | guide_to}` take the bodies from the
MCP tool signatures (`{"zone": "concourse"}`, `{"poi": "kasse", "lang": "fr"}`, ...). Every body accepts an optional
`rationale`. `POST /task {"text", "requested_by"}` runs the headless agent, the same entry ClawMetry's Physical AI
console uses.

## Brain endpoints

### `POST /frame`: frames in, verdict out
* **Request:** `multipart/form-data` with `frame` (JPEG, at most 640x360) and `meta` (JSON:
  `{"ts", "seq", "pose": [x, y, yaw], "zone", "judge": "<trigger>" | null, "poi", "action"}`).
* **Behaviour:** a frame whose `judge` is a trigger name (`guide_start`, `every_2m`, `scene:<class>`, `hazard`,
  `staged_breach`) goes to Cosmos. The verdict is returned and also posted to the edge's `/verdict`.
* **Response:** frames without a trigger only update counters: `{"ok": true, "judged": false}`. A judged frame
  returns `{"ok": true, "judged": true, "verdict": {...}}`.
* **Storage:** the JPEG is dropped when the call returns; no frame is written anywhere.

Verdict JSON (the judge's contract plus what the relay adds):
```json
{"leaves_go_zone": false, "hazards": [], "people_within_2m": 0, "stop": false, "confidence": 0.98,
 "reason": "Straight ahead is a tiled floor, no steps or obstacles, no people in the way, safe to proceed",
 "latency_s": 1.364, "cached": false, "model": "nvidia/Cosmos-Reason2-2B", "frame_hash": "<24 hex chars>",
 "trigger": "hazard", "frame_ts": 1794692836.59, "pose": [9.98, 4.609, 1.424], "zone": "bath_entrance",
 "action": "forward 2 m at 0.3 m/s"}
```
A failure looks like `{"judge_unavailable": true, "error": "TimeoutError: timed out", "latency_s": 8.0, ...}`.

### `GET /verdicts`
The ring of the last 30 verdicts, oldest first, no frames.

### `GET /health`
`{"ok", "cosmos": bool, "frames_seen", "verdicts", "last_frame": {"ts", "seq", "zone", "pose", "bytes", "received"},
"judge": {"calls", "failures", "last_latency_s"}}`

### `POST /ask`
The concierge's Anthropic tool loop. The edge calls it; the adapter should call the edge's `/ask` instead, so the
exchange lands in the robot's journal. Request `{"text", "lang", "session", "name"}`; response as for the edge's `/ask`.

### `POST /describe`
Multipart `frame` and `meta: {"question"}`, returning `{"description": "..."}` (Cosmos; used by the edge's `/look`).

### Console
`GET /` (login form, then the page), `POST /login`, `GET /api/zones`, `GET /pois`, and `GET|POST /api/edge/<x>`:
an allow-listed proxy to the edge (`state`, `observation`, `pause`, `resume`, `say`, `guide_to`, `approve`, `deny`,
`reset`, `confirm`, `ask`, `refix`).
- `GET /api/pipeline` (polled every 2 s): seven tiles `{level: ok|warn|bad, label, detail}` (vLLM `/health`, brain relay,
  edge `/state` RTT, team ROS bridge connected / ctrl_mode / state age, team detector `/latest.json` age, ClawMetry
  journal flush age, `tailscale ping` RTT to the EDGE_URL host every 5 s) and `counters` (`turns_today`,
  `judge_calls`, `dataset_clips`). An unreachable edge makes its dependants red, never green.
- `GET /api/events`: the edge's `/events` SSE, filtered to operator events (`fsm.transition`, `judge_verdict`,
  `hazard`, `breach_predicted`, `person_near`, `approval`, `link_lost` / `link_restored`, `recover`, `guide`, `greet`,
  `concierge.turn`, `command` hold_pose). `event: down` when the edge stream ends.
- `/?watch=1`: full screen, no buttons, for the demo screen and the recording. No camera images anywhere.
- The edge's `/state` carries `pipeline: {detector: {kind, age_s, stale_s}, journal: {on, flush_age_s}, turns_today}`.

## One judge implementation

The Cosmos prompt, the request (temperature 0, max_tokens 150, 8 s timeout, no `<think>`), the robust JSON parsing and
the frame-hash cache all live in **`brain/relay.py`** (`CosmosJudge`, `parse`, `prompt`). Nothing else talks to Cosmos.
The edge sends frames, `scripts/cosmos/judge_probe.py` imports the same class, and the adapter reads verdicts from
`/verdicts` or the edge's `/events`. Do not add a second judge client in the adapter; ask for a field on the verdict
instead.

## Three curl examples

```bash
# 1. Poll state and the safety FSM (adapter heartbeat)
curl -s -H "X-Api-Key: $EDGE_API_KEY" http://edge:8765/state | jq '{fsm: .safety.state, zone: .robot.zone, people: .observation.people_within_2m}'

# 2. A guest goal: guide to the Therme entrance (returns at once; follow progress on /events)
curl -s -X POST -H "X-Api-Key: $EDGE_API_KEY" -H 'content-type: application/json' \
     -d '{"poi": "bath_entrance", "lang": "de", "wait": false, "rationale": "guest at the kiosk"}' http://edge:8765/guide_to

# 3. Follow every safety / concierge event live (SSE)
curl -sN -H "X-Api-Key: $EDGE_API_KEY" http://edge:8765/events | grep --line-buffered '^data:' | cut -c7- | jq -c '{kind, source, to, reason}'
```
